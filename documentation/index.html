Dialzen

AI voice call agent software as a service, built with Next.js 16, React 19 and Tailwind CSS 4. Your customers build AI phone agents that answer inbound calls, book appointments into Cal.com or Google Calendar, answer questions from a knowledge base and make consented follow-up calls, with every call logged with its transcript, summary, sentiment, extracted data and recording. Thank you for your purchase! This guide takes you from download to a live platform with paying customers.

Quick start: upload the dialzen folder, run npm install and npm run build, start the app and open your domain: the web installer does the rest. Then read four chapters before inviting customers: Background jobs (campaigns only dial, and calls are only reconciled and recordings copied, when something calls the cron URL every minute), Voice providers (paste your ElevenLabs and/or Retell keys and the webhook URL), Telephony & numbers and the Compliance guide.

Introduction

Dialzen lets you run your own AI voice agent platform. Your customers sign up, create a workspace per business or client, and:

  • Build an agent. Start from one of 8 templates (receptionist, appointment booking, lead qualification, customer support, order status, reminder and confirmation, feedback survey, real-estate inquiry), let the AI assistant write the prompt from a business description, pick a voice and language, add a knowledge base (PDF, Word, text, web pages) and tools (Cal.com or Google Calendar booking, webhooks to n8n/Zapier/Make, Google Sheets, transfer to a person).
  • Test it in the browser, then connect a phone number (bought in the US/Canada or brought from Twilio or a SIP trunk) and let the agent answer, or embed the agent on a website as a voice widget.
  • Call contacts who agreed to be called. Import contacts with their consent records, then run campaigns (reminders, confirmations, follow-ups) with calling windows in each contact's time zone, retries and pacing. Every call is checked right before dialing against consent, do-not-call lists, opt-outs, calling hours, frequency caps and country rules.
  • Review every call: recording, transcript, summary, sentiment, extracted fields (for example the appointment time), tool calls and cost; analytics with answer rates, outcomes and bookings.

Dialzen is the control plane: agents, knowledge bases, tools, numbers, contacts, consent records, do-not-call lists, campaigns, call credits and the audit log live in your database. A managed voice provider runs the real-time audio loop (speech recognition, the language model and the voice): ElevenLabs Agents or Retell AI, with your platform keys. A Simulated provider runs demos and tests without any real call. Dialzen talks to the providers over REST and receives their events over signed HTTPS webhooks, so it needs no media server and runs on a VPS, cPanel Node.js hosting, Docker or Vercel.

You earn money in two ways: plans (agents, numbers, simultaneous calls, included minutes, team seats, outbound calls, campaigns, API, white label) and call credits: you set a sell price per minute per provider, and workspaces pay for minutes beyond their plan's included minutes from a prepaid wallet (credit packs, auto-recharge). The admin panel shows each tenant's revenue against what the providers charged you (P&L). Customers pay through Stripe, PayPal, Razorpay or bank transfer.

Words used in this guide: you or the operator run the platform. Customers or tenants sign up on your platform and own workspaces. Members are the people in a workspace. Contacts are the people an agent talks to. A provider is ElevenLabs Agents, Retell AI or the Simulated provider. In the examples your platform lives at https://voice.example.com.

Compliance notice: please read

Automated and AI-voice phone calls are regulated. Depending on where you, your customers and the people they call are, laws such as the US Telephone Consumer Protection Act (TCPA) and Telemarketing Sales Rule, US state laws, the EU AI Act, GDPR and the ePrivacy rules, the UK PECR, India's TRAI regulations and call-recording laws govern consent, do-not-call registries, calling hours, caller identification, AI disclosure and recording.

You, as the operator, and each of your tenants are responsible for complying with the laws that apply to your and their calls. Dialzen provides tools that help (AI disclosure in the first message, consent records, do-not-call scrubbing, opt-out detection, calling hours, recording notices, outbound approval with KYC, kill switches and an audit log). These tools are not legal advice and don't make any use of the software lawful by themselves. Have your terms of service, acceptable-use rules and your tenants' use cases reviewed by a lawyer in the countries you serve before you enable outbound calling.

Dialzen is designed for inbound support, appointment booking and consented follow-ups and reminders. Don't use it, or let tenants use it, to call people who haven't agreed to be called.

Providers and carriers have costs and rules of their own. ElevenLabs and Retell bill you per minute and limit how many calls run at the same time; phone numbers cost a monthly fee and some countries require business documents before a number is issued. Read Voice providers and Telephony & numbers before you set your prices.

Installation

Pick the guide that matches your hosting. Every method ends with the web installer. Right after installing, set up a 1-minute scheduler, file storage and your voice providers.

Install Dialzen on its own domain or subdomain with HTTPS, for example https://voice.example.com. The webhook URLs you paste into ElevenLabs (…/api/voice/webhook/elevenlabs), the agents' tool endpoints (…/api/voice/tools/…), the Google OAuth redirect URI (…/api/oauth/google/callback), the widget snippet your customers paste into their sites (…/dz-widget.js) and the cron URL are all built from this address. Changing the domain later means updating the ElevenLabs webhook and the Google redirect URI, re-syncing every agent and number (so Retell gets the new URLs), and asking customers to update their widget snippets.

cPanel / shared hosting (Setup Node.js App)

  1. In cPanel open MySQL® Databases. Create a database and a user, then add the user to the database with All privileges. Write down the database name, username and password.
  2. Create the subdomain (e.g. voice.example.com) in Domains and turn on SSL/TLS Status → Run AutoSSL so it has HTTPS.
  3. Open File Manager, upload dialzen.zip (the app folder of the repository, zipped) to your home folder, e.g. /home/youruser/dialzen, and extract it. Do not put it inside public_html.
  4. Open Setup Node.js App → Create Application:
    • Node.js version: the newest available (22.x recommended)
    • Application mode: Production
    • Application root: dialzen
    • Application URL: your domain or subdomain
    • Application startup file: server.js
    Click Create.
  5. Click Run NPM Install and wait until it finishes.
  6. Copy the command shown at the top of the page (it looks like source /home/youruser/nodevenv/dialzen/22/bin/activate && cd /home/youruser/dialzen). Open Terminal in cPanel, paste it, then run: 
    npm run build
    The build first bundles the web widget (public/dz-widget.js), then the app. It takes 1–4 minutes.
  7. Back in Setup Node.js App, click Restart. Open your domain: you will see the installer.
  8. After installing, add the cron job from Admin → System (see Cron URL). On cPanel this is required: Passenger stops idle apps, and lazy mode only runs while people use the site, so campaigns would stall at night.

server.js starts the built Next.js app, which serves everything: pages, the API, webhooks, tool endpoints, the widget scripts, local files and the files in public. You don't need to copy anything into public_html.

If the build stops with “JavaScript heap out of memory” your plan limits memory. Build on your own computer instead (npm install && npm run build), then upload the whole folder including the .next folder and the generated public/dz-widget.js and public/dz-widget-call.js, and only run “Run NPM Install” + “Restart” on the server.

VPS (Ubuntu) with PM2 and Nginx

  1. Install Node.js 22, Nginx and PM2: 
    curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs nginx
sudo npm install -g pm2
  2. Install MySQL (or use SQLite and skip this step): 
    sudo apt install -y mysql-server
sudo mysql -e "CREATE DATABASE dialzen CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'dialzen'@'localhost' IDENTIFIED BY 'choose-a-strong-password';
GRANT ALL PRIVILEGES ON dialzen.* TO 'dialzen'@'localhost'; FLUSH PRIVILEGES;"
  3. Upload the dialzen folder to /var/www/dialzen, then build: 
    cd /var/www/dialzen
npm ci
npm run build
  4. Choose a cron secret and start the app and the worker with PM2. ecosystem.config.cjs starts two processes: dialzen (the web app) and dialzen-worker (runs the background jobs every 15 seconds). Both get the same CRON_SECRET: 
    export CRON_SECRET="$(openssl rand -hex 24)"
echo "$CRON_SECRET"          # keep a copy
pm2 start ecosystem.config.cjs
pm2 save && pm2 startup

    Always set your own CRON_SECRET before pm2 start. Without it the worker exits (PM2 prints a warning). A CRON_SECRET line in .env.local is only seen by the worker, not by the app started through PM2, so export the variable (as above) or write it into ecosystem.config.cjs. Use at least 12 random characters: the app ignores shorter values and the example value change-me-to-a-long-random-string. After changing it run pm2 restart ecosystem.config.cjs --update-env.

  5. Create /etc/nginx/sites-available/dialzen: 
    server {
    listen 80;
    server_name voice.example.com;
    # Largest upload (knowledge-base documents): keep it above
    # "Largest document or audio file (MB)" in Admin → Settings → Media storage.
    client_max_body_size 50m;

    # Uploads to local storage are streamed to disk: don't buffer them.
    location /api/media/upload {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_request_buffering off;
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_read_timeout 90s;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
    client_max_body_size matters: Nginx's default is only 1 MB, so without it larger knowledge-base uploads fail with 413. X-Forwarded-For is used for rate limits, X-Forwarded-Proto for secure cookies. Enable the site and add a free SSL certificate: 
    sudo ln -s /etc/nginx/sites-available/dialzen /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d voice.example.com
  6. Open https://voice.example.com to run the installer. Afterwards, Admin → System → Scheduler should show Running with the source worker within a minute.
Keep instances: 1 for the web app in ecosystem.config.cjs: rate limits are kept per process. If you ever run several app servers, set the same APP_SECRET and NEXT_SERVER_ACTIONS_ENCRYPTION_KEY on all of them and use S3-compatible storage (or a shared storage folder). The worker calls SITE_URL or http://localhost:3000; set WORKER_URL if the app listens elsewhere.

Docker

The app folder includes a Dockerfile and a docker-compose.yml with three services: app (the web app), worker (runs background jobs every 15 seconds) and db (MySQL 8.4). First create a file named .env next to docker-compose.yml with your own secret:

CRON_SECRET=paste-a-long-random-string-here

Then start everything:

cd dialzen
docker compose up -d --build

Open http://your-server:3000. In the installer choose MySQL with host db, port 3306, database dialzen, user dialzen, password dialzen (change these and MYSQL_ROOT_PASSWORD in docker-compose.yml first). The storage folder (configuration, the generated app secret, uploads and recordings on local storage) is kept in a Docker volume. Put Nginx, Caddy or Traefik with HTTPS in front of port 3000 (with a large enough upload size, see the Nginx example above), and make sure it sends X-Forwarded-For and X-Forwarded-Proto.

docker-compose.yml refuses to start until CRON_SECRET is set in the .env file next to it (at least 12 random characters). The included .dockerignore keeps local node_modules, .next and storage folders out of the image. The image build runs npm run build, which also builds the widget scripts.

Without Compose:

docker build -t dialzen .
docker network create dialzen-net
docker run -d --name dialzen --network dialzen-net -p 3000:3000 \
  -e CRON_SECRET=your-secret -v dialzen-storage:/app/storage dialzen
docker run -d --name dialzen-worker --network dialzen-net \
  -e WORKER_URL=http://dialzen:3000 -e CRON_SECRET=your-secret dialzen node scripts/worker.mjs

Vercel (with TiDB Cloud and Cloudflare R2 or Vercel Blob)

Dialzen needs no media server: the voice providers stream the audio, and your app only answers REST calls, webhooks and tool requests, which works on Vercel's serverless functions. Vercel has no permanent disk, so the web installer, SQLite and local file storage can't be used there. Dialzen is configured with environment variables, a cloud MySQL-compatible database such as TiDB Cloud Serverless (free tier), Aiven or PlanetScale, and an object store for knowledge-base files and recordings: Cloudflare R2 (or any S3-compatible bucket) or Vercel Blob. Blob files are public, so call recordings are never copied there: with Blob, members play them straight from the voice provider.

  1. Create a database. In TiDB Cloud: create a Serverless cluster in the region closest to your Vercel functions, open Connect, generate a password and note the host, port (4000), user and password. In the SQL editor run CREATE DATABASE dialzen;
  2. Create the file storage: an R2 bucket with a public custom domain and a CORS rule (see File storage), or a Vercel Blob store (Vercel → Storage → Create → Blob, then connect it to the project; Vercel adds BLOB_READ_WRITE_TOKEN automatically).
  3. Fork this repository on GitHub (or push your copy to your own repository).
  4. In Vercel click Add New → Project, import the repository and set Root Directory to the folder that contains package.json. Keep the default build command (npm run build; it builds the widget first).
  5. Add these Environment Variables: 
    DB_DRIVER=mysql
DB_HOST=gateway01.ap-southeast-1.prod.aws.tidbcloud.com
DB_PORT=4000
DB_USER=xxxxxxxx.root
DB_PASSWORD=your-password
DB_NAME=dialzen
DB_SSL=true
APP_INSTALLED=true
ADMIN_EMAIL=you@example.com
ADMIN_PASSWORD=a-strong-password
ADMIN_NAME=Your Name
SITE_URL=https://voice.example.com
CRON_SECRET=a-long-random-string
APP_SECRET=another-long-random-string

# Files on Cloudflare R2 …
STORAGE_DRIVER=s3
S3_ENDPOINT=https://<account-id>.r2.cloudflarestorage.com
S3_REGION=auto
S3_BUCKET=dialzen-media
S3_ACCESS_KEY_ID=…
S3_SECRET_ACCESS_KEY=…
S3_PUBLIC_URL=https://media.example.com
# … or on Vercel Blob (BLOB_READ_WRITE_TOKEN is added when you connect the store)
# STORAGE_DRIVER=blob
    Instead of the DB_* variables you can set one DATABASE_URL=mysql://user:password@host:4000/dialzen?ssl=true.
  6. Click Deploy. Tables are created automatically on the first visit and the administrator account is created from ADMIN_EMAIL / ADMIN_PASSWORD.
  7. Add your domain in Settings → Domains, and set the same address in Admin → Settings → General → Site URL.
  8. In Vercel open Settings → Functions and choose a region close to your database (and, for snappy tool calls, close to your voice provider; both ElevenLabs and Retell run in the US by default).
  9. Set up the scheduler as described in Vercel & serverless. This step is not optional: Vercel Hobby cron runs only once a day.

Vercel is fine for a demo or a small platform. Keep in mind:

  • Set APP_SECRET (16+ random characters). It encrypts your tenants' own provider keys, tool credentials (Cal.com keys, Google connections) and carrier logins, and signs widget keys. See Environment variables.
  • There is no worker process: campaigns, reconciliation and recording copies depend on an external cron service calling the cron URL every minute (or Vercel Pro cron).
  • Choose S3/R2 or Blob in Admin → Settings → Media storage (or with STORAGE_DRIVER).
  • Vercel Hobby is for non-commercial use. Use Vercel Pro (or a VPS) for a paid platform.

Local computer (for testing or customising)

cd dialzen
npm install
npm run dev

Open http://localhost:3000 and choose SQLite in the installer. Lazy mode is on by default, so background jobs run while you click around. To run them without visiting pages, start the worker in a second terminal (copy the secret from Admin → System → Scheduler):

CRON_SECRET=the-secret-from-admin npm run worker

On Windows PowerShell: $env:CRON_SECRET="the-secret"; npm run worker.

On localhost ElevenLabs and Retell can't reach your webhook and tool URLs. To try the whole app locally, switch on Admin → Settings → Voice providers → Testing → Allow the simulated provider: agents on the Simulated provider have text-chat test calls, simulated numbers and calls that go through the real webhook pipeline (see Simulated provider). For real calls during development, use an HTTPS tunnel (Cloudflare Tunnel, ngrok) and set it as the Site URL, then re-sync your agents.

Web installer

  1. Server requirements: checks the Node.js version and that storage is writable.
  2. Database: choose MySQL/MariaDB (host, port, database, user, password, and Use SSL for cloud databases such as TiDB Cloud, Aiven or DigitalOcean) or SQLite. Click Test connection, then continue.
  3. Site and administrator: enter your platform name, the full site URL (e.g. https://voice.example.com) and the administrator account. Click Install now.

The installer creates all tables and indexes, the three default plans (Free, Pro, Agency), the default pages (About, Privacy policy, Terms of service) and starter blog posts. It writes storage/config.json and locks itself (storage/installed.lock). Sign in at /login. The admin panel is at /admin, the customer dashboard at /dashboard.

Background jobs & scheduling

Pages, the API, webhooks, tool endpoints and the widget answer immediately; that never depends on the scheduler. But dialing campaign contacts, delivering simulated calls, retrying agent syncs, copying recordings, reconciling calls and charging number rentals are background jobs, and something must start them. Read this chapter before you invite customers.

Why Dialzen needs a cron job every minute

A web app only runs when a request arrives; it can't wake itself up at 09:00 to start a campaign. A scheduler tick does that work:

  • A tick every minute (cron URL) dials due campaign contacts within about a minute and keeps retries, calling windows and pacing on time. The worker ticks every 15 seconds.
  • Simulated calls (demo and testing) move from ringing to ended through events that a tick delivers, so without ticks they appear stuck.
  • Lazy mode (the default) runs a tick only after someone opens a page: at night nothing is dialed until the next visitor.
  • Vercel Hobby cron jobs run once a day: a campaign would make one batch of calls per day.
Without a 1-minute cron job or the worker, campaigns don't dial on time, simulated calls don't finish, failed agent syncs aren't retried, recordings aren't copied, low balances aren't reported, auto-recharge doesn't fire and missed webhooks aren't reconciled. Inbound calls, browser test calls, the widget and single calls placed through the API work without it.

The jobs

A tick runs these jobs one after the other within a time budget (cron URL and worker 45 seconds, lazy mode 8 seconds, Run jobs now 25 seconds). A lock in the database makes sure two ticks never run at the same time; whatever doesn't fit is picked up by the next tick. Each job does a small, idempotent slice of work.

The cron secret

  • If the environment variable CRON_SECRET is set (at least 12 characters, not the example value), that value is the secret.
  • Otherwise Dialzen creates a random secret the first time it is needed and stores it in the database.

Open Admin → System: the Scheduler card shows the complete Cron URL (with a Copy button) and a ready-made cron line. New secret replaces a stored secret, e.g. if it leaked; the old URL stops working immediately. While the secret comes from CRON_SECRET, change the environment variable instead and restart.

curl -fsS "https://voice.example.com/api/cron/tick?key=YOUR-SECRET"
curl -fsS -H "Authorization: Bearer YOUR-SECRET" https://voice.example.com/api/cron/tick

GET and POST both work. A correct call answers with a JSON summary, for example {"source":"cron","startedAt":"…","jobs":{"voice-sync":0,"campaigns":4,"auto-recharge":0,"low-balance":0,"dnc-expiry":0,"retention":0,"recordings":2,"reconcile":0,"housekeeping":0},"failed":[],"skipped":[],"durationMs":3120,"skippedLocked":false}. The numbers are the items each job handled. A wrong or missing secret answers 401; more than 30 calls per minute from one IP address answer 429; "skippedLocked":true means another tick was still running.

Faster dialing: the campaign URL (optional)

/api/cron/campaigns runs only the campaign dialer (25-second budget), without the tick lock. It uses the same secret and is safe to call next to the cron URL and the worker (the dialer leases each contact, so nobody is called twice). Call it more often than once a minute when big campaigns need a faster pace, for example from a second cron service every 15–30 seconds:

curl -fsS -H "Authorization: Bearer YOUR-SECRET" https://voice.example.com/api/cron/campaigns

It answers {"dialed":…,"rescheduled":…,"skipped":…,"ended":…,"recovered":…,"durationMs":…}; up to 300 calls per minute per IP address are accepted. Most platforms don't need it: the worker already ticks every 15 seconds, and the Start button and the API kick a campaign off immediately.

Worker (every 15 seconds)

The worker is a tiny Node.js script (scripts/worker.mjs) that calls the cron URL of the running app every 15 seconds. It needs the app to be running and the same secret.

CRON_SECRET=YOUR-SECRET npm run worker

  • Vercel Hobby (free) cron jobs run at most once a day. Use an external service such as cron-job.org or a Cloudflare Worker to open the cron URL every minute (see above). Set CRON_SECRET in Vercel and use the same value in the URL.

How it works

Agent saved→Sync to provider→Call (phone, browser, widget)→Tools: /api/voice/tools/…→Signed webhook: /api/voice/webhook/<provider>→Billing, transcript, analysis, notifications
  • Sync. Saving an agent pushes its prompt, first message, voice, language, behaviour, tools, knowledge base and analysis fields to its provider. The agent page shows Synced, Pending or Error with the provider's message; the voice-sync job retries pending and failed agents every minute and notifies the workspace (agent_sync_failed) when a sync fails. Dialzen remembers which provider account each agent was synced into (your keys or the workspace's own keys); when the account in use changes, the agent is moved (see Agents move with the keys).
  • Tenant tags. Every call carries the workspace, call, agent, campaign and contact ids (ElevenLabs: dynamic variables and user_id; Retell: metadata), so events from your shared provider account are routed back to the right workspace.
  • Webhook ingest. The raw body is verified (HMAC) before anything is read; each event is processed once (idempotency table), so provider retries and reconciliation never bill twice. When a call ends: billing (included minutes, then the wallet), usage, opt-out detection, recording copy, notifications and the campaign update.
  • Tool endpoints. During a call the provider calls /api/voice/tools/<tool>?agent=<agent> with a per agent-and-tool secret header (X-Dialzen-Tool-Secret). Tools answer within about 5 seconds with a short message the agent can say.
Providers can only reach your webhooks and tool endpoints over public HTTPS. Admin → Voice providers shows a warning when the Site URL isn't an https:// address. After changing the Site URL, open each agent and save it (or click Sync) so the provider gets the new URLs.

Simulated provider

The Simulated provider implements the whole provider interface without any external call or audio. It is always available in demo mode; otherwise switch it on in Admin → Settings → Voice providers → Testing → Allow the simulated provider (for testing only; turn it off before you invite customers, or they could create agents that never make real calls).

  • Numbers: “buy” fictional US/CA numbers in the 555 range, or add a simulated number; Simulate an inbound call on a number starts a call you can follow on the Calls page.
  • Calls (inbound, campaign, API) are decided up front from scenario scripts per template (booked, voicemail, no answer, opt-out, transfer…) in English, Hindi or Arabic. Their events go, signed, through the real webhook ingest over the following seconds, delivered by the scheduler, so the dashboard, billing, analytics, opt-outs and notifications behave exactly as with a real provider.
  • Forcing an outcome (testing): a sim_scenario value on an outbound call to a simulated agent picks the scenario instead of chance. Set it as a custom contact field (CSV column sim_scenario, used by campaigns), as a campaign prompt variable, or in the variables of POST /api/v1/calls. Values: completed, booked, opt_out, no_answer, busy, voicemail, failed, transferred and silent. silent is never drawn at random: the call is answered but the agent only speaks after 4 seconds, so it counts as abandoned and lets you test a campaign's abandonment guard (10 answered calls are needed before the guard judges).
  • Test calls are a text chat that looks like a call: the agent answers with your AI provider (Settings → AI) using its prompt, or with scripted replies when no AI provider is set. A voice mode uses the browser's speech recognition and voices (a preview, not phone quality). The chat runs the agent's tools (Cal.com, Google Calendar, webhook, Google Sheets) through the real tool endpoint, so a test booking really books (see Test calls).

Avoiding spam labels

Carriers' analytics label numbers by behaviour. What helps:

  • Keep volume per number low: each number has a daily dial cap (default 100); 50–100 dials a day is a common recommendation. Ramp new numbers up over about two weeks.
  • Don't rotate caller IDs or match area codes to callees: rotation is itself a spam signal (and Ofcom calls it misuse). A campaign's number pool uses the first number under its daily cap rather than rotating.
  • Use separate numbers for inbound and outbound if volume is high.
  • Call only people who agreed, at reasonable hours: complaints and very short calls (people hanging up within seconds) hurt reputation. Keep the agent's first words immediate (the abandonment guard pauses a campaign when answered calls hear silence).
  • Register numbers (CNAM, Free Caller Registry) and get A attestation in the US.

Compliance guide

Research notes, not legal advice. This chapter summarises rules that commonly apply to AI phone calls, as researched in October 2026, with links to the sources. Laws differ by country and state, change often and are interpreted by courts and regulators. The operator and each tenant are responsible for their own compliance; ask a qualified lawyer before enabling outbound calls in a market.

Two kinds of calls are treated very differently almost everywhere:

  • Inbound calls (a person calls your tenant's number and the AI agent answers) are generally the least regulated: disclose that the caller is talking to an AI, give a recording notice when recording, and handle personal data properly.
  • Outbound calls placed by an AI voice are treated like automated or prerecorded-voice calls in the US and many other places: they need prior consent (written consent for marketing in the US), respect for do-not-call lists and calling hours, caller identification and an easy way to opt out.

AI disclosure

  • EU AI Act, Article 50(1): people must be told they are interacting with an AI system, at the latest at the first interaction, unless it is obvious. It applies from 2 August 2026 (Art. 50); fines can reach EUR 15 million or 3% of turnover.
  • US states: California (AB 2905) requires automatic-dialing calls with an artificial voice to say so; Utah (SB 226) requires disclosing generative AI when asked, and up front in regulated occupations. Federal rules (47 CFR 64.1200(b)) require every artificial-voice call to state the caller's legal name at the start and give a callback number.

In Dialzen: every agent's first message always contains an AI disclosure and the business name: a message that doesn't disclose gets a short sentence in front (“Hi, you're speaking with the AI assistant of Bright Smile Dental.”, also in Hindi, Arabic, Spanish, Portuguese, French, Italian and German). The wording is editable but can't be removed. The compliance center holds the legal business name and the callback number, and each call records whether the disclosure was spoken (disclosure_played). Prompts should tell the agent to answer honestly when asked “Am I talking to a robot?”.

United States: TCPA, consent and do-not-call

  • AI voices are “artificial or prerecorded voices” under the TCPA (FCC declaratory ruling 24-17, February 2024). Consequences:
    • Telemarketing (sales, promotions) to mobile and residential lines needs prior express written consent: a signed (including electronic) agreement that names the number and the seller and says consent is not a condition of purchase.
    • Informational calls (reminders, confirmations, account and service calls) to mobiles need prior express consent.
  • Every call (47 CFR 64.1200): identify the business at the start and give a callback number. Artificial-voice telemarketing must offer an automated opt-out (voice or key press) that records the request and ends the call.
  • Revocation: people may revoke consent “by any reasonable means” (saying “stop calling me” counts), and it must be honoured within 10 business days (in force since 11 April 2025).
  • Do-not-call registries: telemarketers must scrub the National DNC Registry. Each seller needs its own subscription (SAN) from the FTC, so each tenant registers and downloads its own extract (FTC Q&A); the safe harbour requires a copy no older than 31 days. Businesses must also keep an internal do-not-call list (kept 5 years).
  • Abandoned calls: no more than 3% of answered calls per campaign per 30 days may be abandoned; a call counts as abandoned when no message starts within 2 seconds of the greeting, so slow AI responses can count.
  • Penalties: USD 500–1,500 per call in private lawsuits, and regulators' fines on top.

Call recording

Recording a call needs the consent of all parties in California, Delaware, Florida, Illinois, Maryland, Massachusetts, Montana, Nevada, New Hampshire, Pennsylvania and Washington (Justia survey); interstate calls usually follow the stricter state, so play a notice on every recorded call. In the EU and UK recordings are personal data with purpose and retention limits.

In Dialzen: agents record by default; the recording notice (“This call is recorded for quality and training purposes.”, editable) is forced on whenever an agent records. Recordings and transcripts are deleted automatically after the workspace's retention (90 and 365 days by default).

European Union and United Kingdom

  • ePrivacy Directive, Article 13(1): automated calls without human intervention for direct marketing need prior consent across the EU; an AI agent very likely counts as automated. Live marketing calls are opt-in or opt-out depending on the member state (directive).
  • GDPR: a lawful basis for every call (consent or legitimate interest), an absolute right to object to direct marketing (Article 21), transparency, and storage limits for recordings and transcripts.
  • UK PECR regulation 19: automated marketing calls need specific consent to automated calls and must give the caller's name and an address or freephone number; live marketing calls must be screened against the TPS (ICO guidance).

In Dialzen: with EU/UK: AI calls need consent (on by default), marketing calls to EU, EEA and UK numbers require an AI-voice, marketing or written consent record. Upload TPS extracts as a do-not-call list. Erasure requests are handled with Erase contact data, Delete call and Delete recording (see Erasure requests).

India (TRAI)

  • The TCCCPR amendment of 12 February 2025 (regulation): commercial calls may not come from ordinary 10-digit numbers. Promotional calls use the 140 series and service/transactional calls the 1600 series, with the entity, headers, templates and digital consent registered on the DLT platform.
  • Unregistered senders of computer-generated promotional calls over SIP/PRI can be disconnected and blacklisted.

In Dialzen: outbound marketing calls to +91 numbers are blocked (india_dlt_required) unless the workspace selects its DLT route (140 or 1600) in Compliance → Calling rules. For inbound calls in India use an Indian carrier such as Exotel over SIP.

  • Idle timeout: a browser call without activity for 5 minutes is ended by the reconcile job.   • When the workspace owner's account is banned, test calls are refused with 403 (“The account that owns this workspace is suspended.”).

Verifying the signature

Every webhook Dialzen sends is signed the same way: notification webhook channels, webhooks created through the REST API, webhook tools during calls and their Test request.

HeaderValue
X-Dialzen-TimestampWhen the request was signed, in Unix seconds (always sent).
X-Dialzen-Signaturesha256= followed by the lowercase hex HMAC-SHA256, keyed with your secret, of the string <X-Dialzen-Timestamp>.<raw body> (the timestamp, a dot, then the body exactly as received). Sent only when the channel or tool has a secret.
X-Dialzen-EventThe event: call_completed, booking_made… for notifications, tool_call for webhook tools, tool_test for a tool's Test.
X-Dialzen-DeliveryA unique id per delivery (notification webhooks), useful to ignore duplicates.

To verify: compute the HMAC over the timestamp header, a dot and the raw body with your secret, compare it with the signature in constant time, and reject timestamps more than 5 minutes old so a captured request can't be replayed later.

import crypto from "node:crypto";

// rawBody: the request body exactly as received (string or Buffer), before any JSON parsing.
function verifyDialzen(headers, rawBody, secret) {
  const timestamp = headers["x-dialzen-timestamp"] ?? "";
  const signature = headers["x-dialzen-signature"] ?? "";
  if (!/^\d+$/.test(timestamp) || Math.abs(Date.now() / 1000 - Number(timestamp)) > 300) return false;
  const expected = "sha256=" + crypto.createHmac("sha256", secret).update(timestamp + "." + rawBody).digest("hex");
  return signature.length === expected.length && crypto.timingSafeEqual(Buffer.from(signature), Buffer.from(expected));
}

In PHP: hash_equals('sha256=' . hash_hmac('sha256', $timestamp . '.' . $rawBody, $secret), $signature), with $rawBody = file_get_contents('php://input'), $timestamp = $_SERVER['HTTP_X_DIALZEN_TIMESTAMP'] and $signature = $_SERVER['HTTP_X_DIALZEN_SIGNATURE'] (also check the age of the timestamp).

Answer with any 2xx status within 8 seconds. Private network addresses are refused unless the server sets ALLOW_PRIVATE_WEBHOOKS=1; redirects are not followed.

Privacy & data retention

Calls carry personal data: phone numbers, voices, what people said. Under GDPR and similar laws your tenants are usually the controllers of their contacts' data and you are their processor; the voice providers (and Twilio or SIP carriers) are your sub-processors, and calls are processed on their infrastructure (mostly in the US). Put this in your privacy policy and offer your tenants a data processing agreement. The default Privacy policy page is a starting point only.

Deleting workspaces and users

Deleting a workspace (Settings → Delete workspace, owner only) or a user with the workspaces they own (Admin → Users → Delete) first cleans up at the voice providers, so nothing keeps answering calls or costing you money, then removes the workspace's agents, numbers, contacts, consents, campaigns, calls, recordings and files from Dialzen:

Campaigns stopped→Live calls closed (not billed)→Numbers released→Agents deleted (with their tools)→Knowledge-base documents deleted
  • Each step uses the account the resources live in: your keys, or the workspace's own keys on a BYO plan. A resource the provider no longer knows counts as removed. Every deletion is audited (workspace.provider_cleanup).
  • Late webhooks are ignored: events that arrive after the deletion find no call and are logged as ignored (“No matching call.”).
  • When a step fails (provider down, key revoked, provider not configured), the rest continues and the leftover is written to the audit log (workspace.provider_cleanup_failed) and listed in Admin → Voice providers → Provider cleanup failed with the workspace, the number, agent or document and the error. A knowledge-base document whose provider is no longer configured is listed too. Retry tries again with your keys, or with the workspace's own keys while they are still saved; leftovers in an own provider account whose keys are gone (deleted with the workspace, or removed) can't be retried: remove them in that account and tick Forget the ones in workspaces' own accounts whose keys are gone.
  • Tip: releasing numbers is now automatic, but check the card after deleting a workspace with bought numbers, and the provider's dashboard if it shows a leftover: a number left at the provider keeps costing you its monthly fee until it is released there.

Performance

  • No audio through your server. The providers stream the calls; your server handles small JSON requests (webhooks, tools, dashboard). One modest VPS serves many concurrent calls.
  • Tool latency matters. Callers hear silence while a tool runs. Tools time out after about 4.5 seconds; host the app close to your provider (US East for ElevenLabs and Retell by default) and keep webhook tools fast.
  • Campaign throughput is limited by concurrency (campaign, plan and platform caps and your providers' lines), not by the dialer: each run dials up to 200 contacts and runs every tick (15 s with the worker). Add the campaign URL for more frequent runs.
  • One process: keep instances: 1; rate limits are per process. The worker and cron can run alongside safely.
  • Database: SQLite is fine for testing; use MySQL/MariaDB/TiDB in production.
  • Rate limits use the connecting IP from X-Forwarded-For: set TRUSTED_PROXY_HOPS correctly behind Cloudflare.

Updating to a new version

  1. Back up the storage folder (it holds config.json with the app secret, uploads and recordings on local storage) and your database.
  2. Replace all files except storage (and your .env file and edited ecosystem.config.cjs, if any) with the new version.
  3. Run npm install and npm run build (it rebuilds the widget scripts).
  4. Restart the app and the worker: pm2 restart all, docker compose up -d --build, or Restart in cPanel.

Database changes are applied automatically the first time the new version starts. Agents, numbers, contacts, calls and API keys are kept; calls in progress finish at the provider and their webhooks are processed after the restart (or by reconciliation). If the release notes mention new agent features, open Admin → Voice providers and check that agents show no sync errors.

Add the consent record (with its real date and wording) or change the purpose if the call really is informational.
Campaign paused “by the abandonment guard”More than the limit of answered calls heard no agent within 2 seconds. Shorten the first message, check the provider's latency (and the voice model), then resume.
Recordings missingThe agent's Record calls is off; the call had no talk time; someone used Delete recording or Delete call (audit log); with Copy call recordings to media storage off, or on Vercel Blob (never copied there), recordings are streamed from the provider only while it keeps them, and only with the same keys the call used (own keys of a workspace that has since lost them can't fetch it); the scheduler isn't running (the recordings job copies them); the storage test fails (Settings → Media storage → Run test); the provider no longer has the audio (copies are tried for 7 days, up to 6 times; the error is stored on the call); the recording is larger than 200 MB; the retention deleted it. Simulated calls have no audio by design.
